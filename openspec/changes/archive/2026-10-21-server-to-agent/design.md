## Context

`bun run server [task…]` starts `packages/server/src/main/main.ts`. It chooses a model, runs one task through the agent loop with a shell, `read_file` and skills, logs the answer, stops the session's processes and exits. Nothing listens on a port. The name dates from `hello-to-server` (2026-10-16), and the `server` capability got it from 85cbb50.

"Server" means three things in the repository now:

| Meaning | Where | This change |
|---|---|---|
| this program | `packages/server`, `bun run server`, "The server SHALL…" in seven specs, README, CI, comments, tests | becomes "agent" |
| the model server it calls | `lms server start`, "LM Studio's server", failure.ts's "The model server at …", `server_error`, the failure table, the tests' `FakeServer` | stays, and says "model server" where it said "server" |
| the exec server | Brief.md C3 and 4.1: the RPC in M1's workspace container | stays |

The user chose the name in explore mode on 2026-10-21, out of `agent`, `agent` now and `app` at M1, `app` (Brief 4.2's name) and `gremlin` (the planned CLI's name). The choice was `agent`, with M1's scheduler, database and `gremlin` CLI going into a new `packages/app` that runs agents.

**Measured on 2026-10-21 with OpenSpec 1.6.0,** in a scratch copy of `openspec/`:
- `validate` accepts a MODIFIED requirement whose scenarios are retitled, but `archive` refuses it: "current spec contains scenario(s) not present in the modified block". `hello-to-server` saw the same.
- Removing and adding a requirement under the same name is refused: "Requirement present in both ADDED and REMOVED".
- This change's deltas archive cleanly. The `server` spec keeps its requirements' order, and so do `skills` and `shell-tool`. Moving `specs/server` to `specs/agent` afterwards, and retitling the three scenarios by hand, leaves `openspec validate --specs --strict` passing for all 12 specs.

## Goals / Non-Goals

**Goals:**
- `bun run agent` and `bun run agent:node` start the agent, with the arguments and settings `server` took.
- The package is `packages/agent`, `@mecha-gremlin/agent`.
- "The server" no longer names this program anywhere people read it: specs, README, CI, comments, test names and helpers.
- Every remaining "server" plainly means the model server or the exec server.
- The capability is `agent`.

**Non-Goals:**
- **Keeping `server` as an alias.** The rename is a clean break, as `hello` → `server` was.
- **Changing behaviour.** Log records, messages, settings and exit codes stay byte for byte. failure.ts's and lmstudio.ts's messages already say "model server" or "LM Studio".
- **Creating `packages/app`.** That's M1's work; this change only records where it goes.
- **Changing Brief.md's records,** which describe the server as it was when they were written: R14, D19's wording, the dated log lines. Only D22, 4.2's layout and a new log line are added.
- **Changing the archive.** Archived changes keep the names they had.

## Decisions

**1. Vocabulary.**
- **"The agent"** names the program, as "the server" did.
- **"The agent's process"** or **"the agent process"** is used wherever the OS process is meant: its environment, its own process and process group, its `PATH`. Inside shell-tool, "the agent's environment" could be read as the world the model acts in, so it's written "the agent process's environment".
- **"The model"** stays the LLM. The specs already say "the model" throughout, so "the agent" never stands for it.
- **"The model server"** replaces a bare "the server" where the model server is meant: the failure table, "the server rejects the API key", "the server's own message", the 429 scenario and "when the server reports them".
- **Already unambiguous, unchanged:** `lms server start`, "LM Studio's server", `server_error`, `FakeServer` and its `server` parameter in tests, lmstudio.test.ts's "explains an unreachable server", and failure.test.ts's "a server error".

**2. The package.**
- **Move:** `git mv packages/server packages/agent`, so history follows the files.
- **`packages/agent/package.json`:**
  - `name` becomes `@mecha-gremlin/agent`;
  - `description` becomes "The mecha-gremlin agent: carries out a task with a shell, read_file and skills". "App" is now the name of M1's package.
- **`bun.lock`:** regenerated by `bun install`, so CI's `--frozen-lockfile` passes. Only its workspace entries change.
- **Unchanged:** the root `tsconfig.json`, `vitest.config.ts` and `stryker.config.mjs`, which glob `packages/*`. Nothing imports `@mecha-gremlin/server`.

**3. The scripts.**
- **Root `package.json`:**
  - `agent` is `bun packages/agent/src/main/main.ts`;
  - `agent:node` is `node --env-file-if-exists=.env packages/agent/src/main/main.ts`;
  - `server` and `server:node` go.
- **Unchanged:** `packages/agent/package.json`'s `start` script.

**4. Code, tests and CI.**
- **Comments:** "the server" becomes "the agent" in `src/config/config.ts`, `src/exec/env.ts`, `src/exec/run.ts`, `src/exec/sweep.ts` and `test/signal-guard.ts`. Where a comment means the process, say "the agent's process".
- **Tests:**
  - `runServer` and `startServer` become `runAgent` and `startAgent`;
  - the `server-*` temp-directory prefixes become `agent-*`;
  - describe titles follow the spec's requirement names, such as "Stop the session's processes when the agent ends";
  - test names follow the scenario titles: "the agent reports a skill without frontmatter", "the agent reports a warning", "the agent's secrets stay out", "no handler outlives the agent".

  The second parameter of `runServer`/`startServer`, `server: FakeServer`, is the fake model server and keeps its name.
- **CI:**
  - the step becomes "Start the agent on Node", running `bun run agent:node`;
  - its comment and its `::error::` message speak of the agent;
  - so do the `NODE_VERSION` comment and the comment on `test:node`.

**5. The spec delta.**
- **MODIFIED,** text only, in seven capabilities:
  - `server`: its first five requirements;
  - `agent-loop`: "Create a session from the configuration and a step limit";
  - `read-file-tool`: "Read a UTF-8 text file under a root directory";
  - `structured-log`: "Log structured records to stdout" and "The log format is checked first";
  - `skills`: "Find skills…", "Read SKILL.md leniently" and "Activate a skill with activate_skill";
  - `shell-tool`: "Run a command with bash…", "Build the command's environment from scratch" and "Stop every process a session started";
  - `result`: "Results as values", whose `core` and `server` become `core` and `agent`.
- **Replaced (REMOVED plus ADDED),** as `hello-to-server` did:
  - "Run the server on Bun or on Node" becomes "Run the agent on Bun or on Node", with the scenario "CI starts the agent on Node";
  - "Stop the session's processes when the server ends" becomes "Stop the session's processes when the agent ends", with the scenario "No handler outlives the agent".

  They are the spec's last two already, and ADDED appends them in that order, so the order stays.
- **Scenario titles kept in the MODIFIED blocks:** "The server reports a skill it can't use", "The server reports a warning" (skills) and "The server's secrets stay out" (shell-tool) keep their titles in the delta, because archive refuses a retitled scenario (Context). Renaming those requirements to get around it would invent names and move them to the end of their specs. Decision 6 retitles the three by hand.

**6. After archiving, by hand, in one commit.** OpenSpec has no rename (85cbb50), so:
- `git mv openspec/specs/server openspec/specs/agent`, and its title line becomes `# agent Specification`;
- the Purpose lines, which deltas don't reach:
  - `agent`: "The agent's entry point, which chooses…", ending "It runs on Bun, with `bun run agent`, or on Node, with `bun run agent:node`.";
  - `agent-loop`: "The agent's loop…";
  - `read-file-tool`: "The agent's `read_file` tool…";
  - `shell-tool`: "The agent's `shell` tool…";
  - `skills`: "How the agent uses Agent Skills: finding and reading…";
  - `structured-log`: "The agent's logger…";
- the three scenario titles:
  - "The agent reports a skill it can't use";
  - "The agent reports a warning";
  - "The agent's secrets stay out";
- check with `openspec validate --specs --strict` and `openspec doctor`, then `grep -rni server openspec/specs`. Only model-server meanings should remain.

**7. Brief.md.**
- **D22,** after D21:

## Risks / Trade-offs

- **`bun run server` stops working.** → The proposal marks it BREAKING, and the README's Run section shows the new commands. Once CI is updated, nothing in the repository runs the old scripts.
- **A blind replace would break the model-server text,** both the specs' failure table and failure.ts's messages. → Decision 1 lists what stays, and the post-archive grep checks it.
- **"Agent" has its own overloads:** Agent Skills, `agent-loop`, and Brief.md's "the agent" for the model at work in the workspace. → Decision 1's "agent process" covers the one place a misreading matters. Agent Skills is a proper name, and `agent-loop` reads as the agent's loop.
- **Between archive and decision 6's commit, the spec says "agent" under a `server` folder,** and three scenario titles still say "server". → Both happen on the branch, before it reaches `main`.
- **A local `.env` or shell alias that runs `bun run server`** breaks. → Settings don't change; only the command does.

## Migration Plan

Run `bun run agent` instead of `bun run server`, and `bun run agent:node` instead of `bun run server:node`. A checkout with `node_modules` should run `bun install` once, so the workspace link follows the move. Rolling back means reverting the change.
