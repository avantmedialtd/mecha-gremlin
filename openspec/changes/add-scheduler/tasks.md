- [ ] 2.1 Parse the subcommands `run`, `check`, `install` and `uninstall`, their options `--config` and `--data-dir`, and `--help` and `--version`, by hand in `main.rs` (design decision 2): each option once, only the options a subcommand takes, and anything else, a missing or unknown subcommand included, exiting 1 with the usage on stderr.
- [ ] 2.2 Write `config.rs`: the TOML structs with `deny_unknown_fields`; the defaults; a file that is missing, unreadable or not TOML; durations (a positive whole number with `s`, `m` or `h`); names (ASCII letters, digits, `-` and `_`, at least one, unique); a non-empty `command` from the job or the top; `on_failure` from the job or the top, an empty one meaning none; a `keep_runs` of at least 1; a relative `working_dir` resolved against the config file's folder, with `command`, `args` and `on_failure` left as written; no jobs allowed; and the `env` merge. Every error names the file, and its key and line when there is one.
- [ ] 2.3 For `run`, check that the data directory exists and is a directory, failing with its path.

## 3. Schedules, the zone and the wait

- [ ] 3.1 Write `schedule.rs`: map the nicknames to five fields, `@midnight` included; refuse other `@` words, `?`, `L`, `W`, `#`, a `+` before the day of week, full names, and six or seven fields; parse with croner through `CronParser::builder()` and `Seconds::Disallowed`; refuse a schedule with no next fire; look up `timezone` with jiff, or read the system's zone at each wake from `TZ` or the `/etc/localtime` link, using jiff's `TimeZone::system()` only where that is a plain file.
- [ ] 3.2 Write the due computation as a pure function of a job's schedule, the zone, its last look, now and whether its run is going: the latest fire after the last look and at or before now, on time when seen less than 90 s after it and missed otherwise; `running`, `missed` or a start; and a last look that becomes now unless now is earlier.
- [ ] 3.3 Write `events.rs`: one `mpsc` channel fed by a signal-hook thread for SIGTERM, SIGINT and SIGHUP and by one waiter thread per run, and the loop's `recv_timeout` on the earliest of the next fire, the nearest signal due to a run (its deadline or its SIGKILL) and 60 s. Count fires on the wall clock and deadlines on `Instant`s. Decide once at the start, before the first wait, and record `clock stepped back` when the wall clock reads earlier than at the previous wake.
- [ ] 3.4 Write `check` (design decision 2): check the config as `run` does, print the zone and each job's next 5 fires after now in ISO 8601 with the zone's offset, and exit 0, or exit 1 with the check's message on stderr, using no data directory, lock or file and starting no run.

## 4. Runs, logs and the lock

- [ ] 4.1 Take the lock: create `<data-dir>/lock` with mode 0600 and hold `File::try_lock` for the process's life; a held lock exits 1, naming the data directory.
- [ ] 4.2 Write `log.rs`: append JSON lines to `scheduler.log`, created with mode 0600, holding `time` (ISO 8601 UTC), `level`, `message` and the fields of design decision 11's records, with U+007F to U+009F escaped and times in fields written as `time` is; write errors to stderr until the log is open. Before a record, once the file has reached 10 MiB, counting the bytes written from its size at open, rename it to `scheduler.log.1` and start a new one with mode 0600, carrying on in the open file if the rename fails (design decision 11).
- [ ] 4.3 Write `runs.rs`: start a run with `Command` (the command and `args`, `working_dir`, the merged environment with `GREMLIN_JOB`, `GREMLIN_SLOT` and `GREMLIN_CATCH_UP` set over it, or `GREMLIN_CATCH_UP` removed for a run on time, `process_group(0)`, stdin from `/dev/null`, stdout and stderr appended to `jobs/<name>/<start>.log` in a folder with mode 0700, the log with mode 0600); record `started`, and `exited` from its waiter with the code or signal and the seconds; record `error` when it can't start.
- [ ] 4.4 Act on 3.2's decision: start the job, record `skipped` with the reason `running`, or catch a missed fire up once, or record `skipped` with the reason `missed` when the job sets `catch_up = false`. At the start, read each job's last look from its newest log's name, or take the start time.
- [ ] 4.5 Enforce timeouts: at a run's deadline, SIGTERM to its process group through rustix, SIGKILL `stop_grace` later, and a `timed out` record. A run keeps the `timeout` and `stop_grace` it started with. Keep each run's group as the `Pid` from `Pid::from_child`, never as an integer a function returns, and send nothing to a group below 2; 5.2's stop sends through the same function.
- [ ] 4.6 After each start, delete the job's oldest logs beyond `keep_runs`, never a running run's.
- [ ] 4.7 Start a failed run's `on_failure` command (design decision 17): after a non-zero exit, a signal, a timeout or a start that failed, in the run's working directory and a group of its own, with stdin from `/dev/null`, its output appended to the run's log, and the run's environment with `GREMLIN_RESULT`, `GREMLIN_STATUS` and `GREMLIN_LOG`. Give it 60 s, then SIGTERM and SIGKILL after `stop_grace` through 4.5's function; record `error` when it fails; and start none after a success, a skipped fire or during the stop. A run uses the `on_failure` it started with.

## 5. The start, the signals and the setup

- [ ] 5.1 Record `ready` at the start, with the `zone` and each job's `name` and `next` fire.
- [ ] 5.2 On SIGTERM or SIGINT: record `stopping` with the signal, start no run or `on_failure` command, send SIGTERM to the group of every run and command still going, wait up to `stop_grace`, send SIGKILL to the rest, record `stopped` and exit 0, ignoring further signals.
- [ ] 5.3 On SIGHUP: read and check the config again. Swap it in and record `config reloaded`, letting running runs end with their own deadlines, dropping removed jobs, keeping kept jobs' last looks and giving new ones a last look of now; or record `config refused` with the reason and keep the old one.
- [ ] 5.4 Write `install.rs` (design decision 16): the plist, written by hand with `&`, `<` and `>` escaped; and `install` and `uninstall` as functions of the system's name, the home directory, the user's id, the binary's path, the environment, the waits' limits and a runner for `launchctl`. `install` refuses on any system but macOS, checks the config, creates the data directory and `stderr.log`, boots out a loaded agent and waits for the lock, writes the plist, saying when it replaces one, loads it with `bootstrap` and waits for a `ready` record; `uninstall` boots the agent out and deletes the plist.
- [ ] 5.5 Hand `install` and `uninstall` the real `/bin/launchctl`, `HOME`, rustix's `getuid` and `current_exe` in two small functions, each with `#[mutants::skip]` and its reason on the line above: a test that called them would change the launchd of the machine running it. Run neither `install` nor `uninstall` on this machine; S11 checks them on a spare Mac.
